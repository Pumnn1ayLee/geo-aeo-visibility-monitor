# Apify Store

> Apify Store is the largest marketplace of tools for AI: 90,000+ ready-to-run tools called _Actors_ that let agents and developers collect web data, automate workflows, and connect APIs. An Actor takes a JSON input, runs in the cloud, and returns structured data. This file is regenerated daily from public Store data: it lists the most popular Actors overall and per use case, and the full catalog is searchable via the API below.

## How to run an Actor

Read https://apify.com/agents.md once, then come back here. It is the source of truth for connecting over MCP at `https://mcp.apify.com`, for getting an API token when no human can sign in interactively, for the MCP tool sequence that goes from a search to the dataset items, for the REST endpoints that start a run and read its dataset, and for paying without an Apify account. Headless clients that need a token can sign up at https://console.apify.com/sign-up?utm_source=store.md.

One rule from that document is repeated here, because this file is where an agent picks the Actor it is about to run. **Before the first paid run of a session:** read the Actor's pricing model and estimated cost from its `.md` page or from the Store API's `currentPricingInfo`, tell the user both, and wait for a go-ahead. Once per session, not before every run. Then cap the bill with `maxTotalChargeUsd`, which caps the run's total charge. `maxItems` is no substitute: it becomes a charge cap only on an Actor billed per result, and only when `maxTotalChargeUsd` is unset. Both are query parameters on the REST run endpoints and `callOptions` on the MCP `call-actor` tool. Never put either in the Actor input: there they are read as input fields and cap nothing. Those two cap what is billed, not what the Actor does, so the Actor's own input fields are the real limit.

## How to search the full catalog

`GET https://api.apify.com/v2/store?search={keywords}&category={CATEGORY}&limit=10` is public, needs no auth, and returns JSON ranked by relevance. Search by platform, data source, or a comparable product ("google maps", "amazon", "apollo") rather than by your end goal, because task phrases like "coffee shops in Prague" match poorly. Pass `category=` whenever one fits. Add `sortBy=popularity` only to browse a category's most-used Actors; it overrides relevance and can bury exact matches.

Valid `category` values: AI, AGENTS, AUTOMATION, DEVELOPER_TOOLS, ECOMMERCE, FOR_CREATORS, JOBS, LEAD_GENERATION, NEWS, SEO_TOOLS, SOCIAL_MEDIA, TRAVEL, VIDEOS, REAL_ESTATE, INTEGRATIONS, OPEN_SOURCE, MCP_SERVERS.

A result can carry pricing in `currentPricingInfo`, direct agentic-payment eligibility in `isWhiteListedForAgenticPayments`, and usage stats under `stats` (30-day run counts on most Actors; fetch `GET https://api.apify.com/v2/actors/{username}~{actor-name}` for an Actor missing them).

To read one Actor in full, append `.md` to its lowercase URL: `https://apify.com/{username}/{actor-name}.md` is a markdown mirror with the README, pricing, and input schema. Mixed-case URLs redirect, so follow redirects.

## What the quickstart does not cover

- **Recurring runs.** Create a Schedule with a cron expression (`POST /v2/schedules` — https://docs.apify.com/actors/running/schedules.md), and attach a webhook (`POST /v2/webhooks`) to push each finished run's results to your endpoint or chain another Actor.
- **Metering a wallet-funded token.** An agent paying through the account-free path in the quickstart holds a prepaid, spend-capped token from https://agi.apify.com. Track its spending through each run's `usageTotalUsd` (`GET https://api.apify.com/v2/actor-runs`, Bearer auth) rather than the AGI balance endpoint, which settles with a delay.
- **The rest of this site.** https://apify.com/llms.txt indexes every other page on apify.com as markdown. The quickstart names the platform documentation index; this is the site one.

## How to read the entries below

Each entry follows the template `- [name](url) — description (users, rated R/5 (N reviews), pricing model)`; the facts are always the last parenthesised group, and the name and URL are the markdown link that opens the line. The description and its ` — ` separator are omitted for Actors without a description, the rating is omitted for Actors without reviews, and the pricing model is omitted for an Actor still on a retired model. Pricing models: "pay per event" means fixed developer-set prices per result or other action; "pay per event + usage" adds the compute a run consumes; "pay per usage" means you pay for the compute a run consumes. When present, exact prices are in the Store API's `currentPricingInfo` (tiered by plan — the FREE tier is what a new account pays); Actor `.md` mirrors usually include pricing too.
